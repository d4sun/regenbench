# T0.1 — Host Specification & Verification

The host runs no torch/sklearn — all scanner and oracle dependencies live
inside the containers. The host needs Python (for the harness), a container
runtime, and network access to Hugging Face Hub (for the crawl only).

| Requirement | Minimum | Checked by |
|------------|---------|------------|
| CPU | 4 cores (6+ for full concurrency) | `scripts/verify_host.sh` |
| RAM | 16 GB total | `scripts/verify_host.sh` |
| Free disk (root `/`) | 50 GB (corpus + images + campaign DB) | `scripts/verify_host.sh` |
| Container runtime | `podman` **or** `docker` (daemon reachable) | `scripts/verify_host.sh` |
| Python | >= 3.13 (`python3`) | `scripts/verify_host.sh` |
| Host deps | `PyYAML`, `huggingface_hub` | `README.md#Prerequisites` |
| Concurrency | 6 containers start concurrently | `scripts/verify_host.sh` |
| SELinux `:ro,z` mount | shared-label mount readable inside a container | `scripts/verify_host.sh` |
| Network | Hugging Face Hub reachable (crawl) | `scripts/crawl_benign.py` |

Run the gate:

```sh
./scripts/verify_host.sh     # exits non-zero if any check FAILs
```

## Why the SELinux mount check matters

Scanner containers mount the artifact under test with `:ro,z` (a *shared*
relabel). The original code used `:ro,Z` (a *private* relabel): when two
scanners mounted the same checkpoint concurrently the relabels raced and
containers intermittently crashed with `PermissionError`, which some scanners
(Fickling) reported as *malicious* — a nondeterministic FP. `verify_host.sh`
mounts a probe with `:ro,z` and reads it back to confirm the mechanism works
on this host. See `scripts/verify_host.sh:127`.
